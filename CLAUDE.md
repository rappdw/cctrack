# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

cctrack-py is a zero-dependency Python CLI that scans Claude Code and Codex CLI log files and reports token usage and estimated cost. It's a Python port of the Go-based [cctrack dashboard](https://github.com/ksred/cctrack), stripped down to a single command that parses logs and prints a cost report.

## Commands

```bash
# Install in development mode
uv pip install -e .

# Run the tool
python -m cctrack
# or after install:
cctrack

# Run all tests
python -m pytest tests/

# Time a run: per-phase wall time on stderr (also per --remote host); stdout unchanged
CCTRACK_TIMING=1 python -m cctrack

# Benchmark on a synthetic corpus (add --remote for a fake host); run 1 cold, later runs warm
python3 scripts/bench_cache.py --filler-lines 6 --runs 3

# Parse cache: read everything and replace it / read everything and leave it alone
cctrack --rebuild-cache
cctrack --no-cache   # or CCTRACK_CACHE=0

# Run a single test
python -m pytest tests/test_cctrack.py::test_name

# Build distribution
uv build
```

## Architecture

This is a single-module CLI tool. All logic lives in `src/cctrack/__init__.py`:

1. **Rate card** (`RATES`, `_an`/`_oa` row builders, `_family_matches`, `get_rates`, `calculate_cost`, `is_known_model`) - Anthropic and OpenAI prices. **Every model version needs its own row**: `_family_matches` lets a row absorb only the exact id, dated snapshots (`-20250514`, `-2025-08-07`) and non-version suffixes (`-codex`) — never a short-number minor version (`claude-opus-5` does NOT match `claude-opus-5-5`) or a size-tier word (`mini`, `nano`, `pro`, `max`, `luna`, `terra`, `sol`, `astra`). This is deliberate: prefix inheritance silently mispriced opus-4-8 (3×) and opus-5-5 (84%) before. Unknown models are flagged `?` and fall back to Sonnet (Claude) or GPT-5 (OpenAI) rates. `get_rates` takes the usage date (time-limited `intro` pricing) and the request's prompt size (`long_context` tiers: historical Sonnet 4/4.5 >200K, Haiku 5.5 >100K, several OpenAI models >272K). Re-verify against the official pricing pages when adding rows; don't infer a price from a neighbouring model. `_find_rate_row` is memoised per model string (`_find_rate_row_uncached` is the real lookup); the memo rebuilds itself when `RATES` or `MODEL_ALIASES` is replaced by another object or changes length, so tests patch by replacing them, never by editing an element in place. Don't memoise `get_rates`/`calculate_cost` (date, prompt size and tier vary) or `energy_scale()` across calls.
1a. **Energy model** (`ENERGY_WH_PER_MTOK`, `estimate_energy_wh`) - Opt-in (`--energy`) order-of-magnitude estimate keyed off each rate entry's `tier`. Deliberately NOT a function of price: both cache-write TTLs use one figure because a 1h write costs more money but the same compute.
2. **File discovery** (`sandy_home`, `_sandy_print_state`, `sandbox_roots`, `default_dirs`, `discover_files`) - Claude transcripts from `~/.claude/projects/` plus each Sandy sandbox's `claude/projects/` (ONLY `projects/` — `claude/` also holds `history.jsonl`, job timelines, tool-audit logs). Sandbox roots come from scanning `$SANDY_HOME/sandboxes/*` (default `~/.sandy`), locally and remotely. `sandy --print-state` (`sandboxes[].path`) is asked ONLY when that dir is missing — it takes many seconds and was called 3× per run, which made cctrack look hung. It is cached per run, gets stdin=/dev/null, and has a `CCTRACK_SANDY_TIMEOUT` (default 15s) with a fallback note. Per sandy's host-side path contract each root has agent homes `claude/` (→ `~/.claude` in the sandbox) and `codex/` (→ `~/.codex`); everything else under a root is private. **Dot-entries** (`_is_sandbox_name`): skip `.rsync-from.*` (an in-progress `sandy --rsync-from` copy — its hook data was being summed twice) and `*.lock`; any other dot-dir is a REAL sandbox iff it holds `WORKSPACE.json` (a workspace like `~/.dotfiles` → sandbox `.dotfiles-<sha8>`). Sandy's own enumeration, hence `--print-state`, currently omits dot-named sandboxes; the directory scan finds them. Tests are isolated from real sandboxes by `tests/conftest.py`.
2a. **Codex** (`codex_homes`, `discover_codex_files`, `parse_codex_lines`, `parse_codex_events`, `fetch_remote_codex`) - Reads `$CODEX_HOME` (default `~/.codex`) and every sandbox's `codex/` (sandy never sets CODEX_HOME), `sessions/` + `archived_sessions/` rollouts, incl. `.jsonl.zst` (stdlib `compression.zstd` on 3.14+, else the `zstd` CLI, else skipped and counted). Lines are `{timestamp, type, payload}`. Reconcile `token_usage_record` items with their matching `event_msg`/`token_count` snapshots; never discard the rest of a file after its first record. Keep standalone compaction usage, last-only and cumulative-only snapshots; dedup unchanged cumulative re-emissions. Prefer the record's explicit model and recorded service tier. Forked legacy usage is matched against the parent's sequence, preserving history through repeated merges and nested forks; missing parents retain uncertain usage flagged UNKNOWN. **`input_tokens` includes `cached_input_tokens` and `cache_write_input_tokens`; `output_tokens` includes reasoning** — uncached input = input − cached − cache_write. Model/cwd from the latest `turn_context`; thread id + git branch from `session_meta`. Codex events carry `agent="codex"`.
3. **Remote aggregation** (`fetch_remote_bundle`, `_remote_program`, `_remote_collect_files`, `_assemble_remote_bundle`, `_remote_collect`, `_parse_remote_files`, `parse_hook_blob`, `remote_sandbox_roots`, `fetch_remote_jsonl`, `parse_remote_events`, `fetch_remote_hook_data`, `parse_remote_hook_data`, `fetch_remote_codex`) - **Default: parse on the host.** `fetch_remote_bundle` sends this module's own source (zlib+base64) to `ssh host python3 -`; `_remote_collect_files` runs there (read-only; no hook rollup; never opens a cache) and returns protocol v2: per file, in discovery order, either a hit marker (its `(size, mtime_ns)` matches the manifest the local side embedded in the program) or that file's own `{events, stats}` / hook rows — never deduped across files. The local side (`_assemble_remote_bundle`) loads hits from the cache, stores misses (host key `remote:<name>`, code = local code key + `["remote", host, rkey]` where rkey is the remote interpreter and encoding), and runs `dedup_events` and the hook sort itself; a hit it can't supply triggers one full refetch. Remote hook files keep the blob semantics (`_hook_rows_from_blob_text`; a file containing the monthly/baseline separators makes the remote return v1's whole-blob hook result). `_remote_collect` is the v1-shaped equivalent. The reply is zlib-compressed tagged JSON (`_tag_json`/`_untag_json` round-trip tuples, sets, datetimes, non-str keys — never pickle). Remote `Progress` emits `CCTRACK_PROGRESS` stderr lines that `_run_streaming` relays into the local status line. Bundles are memoised per host for the run (`_remote_bundle_cache`; not the parse cache); the parse_remote_* functions read the bundle. `{"failed"}` (ssh error 255, timeout) means no retry; `{"fallback"}` (no python3 / <3.10 / unreadable reply, or `CCTRACK_REMOTE_PARSE=0`) streams raw: one SSH call finds sandbox roots (same rules as locally, cached), then each fetch cats the host's dirs with file separators, gzip-compressed in transit (`_gzip_wrapped`/`_decode_stream`), and parses locally. `tests/test_remote_parse.py` runs both paths against one fake host via a fake `ssh` and requires identical events, stats and hook rows; `tests/conftest.py` stubs `fetch_remote_bundle` unless marked `real_remote_bundle`. All ssh runs through `_run_ssh`: `ssh -T`, stdin=/dev/null, local termios saved/restored (a timed-out ssh once left the terminal raw → staircased report). Fetch timeout `CCTRACK_SSH_TIMEOUT` (default 600s); a timeout warns that the host's data is MISSING. `Progress` draws a cylon bar + bytes/files on stderr only when it's a TTY (`CCTRACK_NO_PROGRESS` disables).
3a. **Hook parsing** (`parse_hook_rows`, `compute_hook_deltas`) - The hook gives **cost only**. Its `input_tokens`/`output_tokens`/`cache_*` fields are context-window SNAPSHOTS (`input_tokens` ≈ `cache_read + cache_write`; `output_tokens` is just the last message's), not cumulative — never use them for token counts. `cost_usd` is a session-lifetime cumulative that is unreliable in two ways handled by `compute_hook_deltas`: (1) it can already be large the first time a session is observed (a long-running/unattended session that only rendered its statusline partway through), so the **first observation is a baseline that is NOT counted** — booking a session's pre-existing cumulative onto its first-seen day is what produced a bogus $3,370 day; (2) it **drops** on resume/compaction (or when parallel processes share one session id), so a drop **rebaselines without counting the new level** — otherwise a day's booked spend can exceed the counter's own peak, which is impossible for real money. Net rule: **book only observed upward increments**; a rolled-up baseline seeds `prev` so already-counted days aren't recounted.
3b. **Hook install** (`install_hook`, `uninstall_hook`, `_apply_hook_install`, `_apply_hook_uninstall`, `remote_*_hook`, `HOOK_SCRIPT`) - The hook is Claude Code's `statusLine` command. Install **wraps** any existing status line: it's saved as `wrapped_status_line` in `~/.claude/cctrack/config.json` (other statusLine keys like `padding` are kept), and `HOOK_SCRIPT` records the cost and then runs it via the shell with the same stdin, passing stdout and exit code through. Re-install keeps the saved command and `installed_at` (the start of hook coverage). Uninstall restores the wrapped line only if `statusLine` still points at cctrack. `_apply_hook_*` are self-contained (imports inside) because `remote_*_hook` ship their source with `inspect.getsource` to `ssh host python3 -`. Local and remote share one implementation, and tests run that shipped program for real.
4. **JSONL parsing** (`parse_lines`, `parse_events`, `dedup_events`) - Extracts `assistant` events with token usage. Deduplicates by message + request identity, falling back to Anthropic message id scoped to the session when request id is absent, and then request id when older logs omit message id. Gateway message ids without request ids also include timestamps. Keep the fullest snapshot, prefer parent messages over sidechain replays, and count advisor iterations separately. `reconcile_sources` performs the final cross-host merge and rebuilds source costs so all report modes agree. Preserve copy locations in JSON/CSV. `_parse_log_file`/`_parse_log_lines`/`_read_log_lines` are the one per-file seam (one file → `{events, stats}` or `None` = unreadable) used by `parse_events`, `parse_codex_events` and `_parse_remote_files`; the local-only `agent-<id>.jsonl` fallback is its `agent_id_from_name` flag. Plain files are split by `readlines()`, `.zst` text by `splitlines()` — deliberately different (U+2028).
4a. **Parse cache** (`open_cache`, `CacheStore`, `_parse_log_file_cached`, `_encode_cache_payload`, `cache_code_key`, `cache_mode`) - Local Claude transcripts and Codex rollouts go through it: `main` opens the store once (unless `cache_mode` says off), passes it to `parse_events`/`parse_codex_events`, and closes it in its `finally` (never switching timing phase while unwinding). One SQLite file `cache.sqlite3` under `$CCTRACK_CACHE_DIR` / `$XDG_CACHE_HOME/cctrack` / `~/.cache/cctrack` (dir 0700, file 0600), one entry per log file keyed `(host, kind, path)`, valid while `(size, mtime_ns)` and the code key (module sha256 + interpreter + marshal version + default text encoding + parse params) match. Payload is `zlib(marshal({events, stats}))` encoded at `put` time, before any cross-file dedup (dedup mutates fork parents' `_locations`); zlib's checksum makes a corrupt blob a miss. Racy (mtime within 2 s, or changed during the read) and failed parses are never stored; a `.zst` hit needs a decoder. `--no-cache`/`CCTRACK_CACHE=0` never opens the file (opening writes); `--rebuild-cache` deletes and refills it; the flags are exclusive and beat the env var. Local hook files (`parse_hook_rows(dir, cache=)`, kind `hook`, after `rollup_old_hook_files`) and `--remote` hosts (item 3) go through it too; the raw stream never does. `sqlite3` is imported lazily; any store error prints one `cctrack: cache ...` note and the run continues uncached. `tests/conftest.py` gives every test its own `CCTRACK_CACHE_DIR`; the harness's `run_env` defaults to `CCTRACK_CACHE=0`, and `run_launched` (an `open` audit hook) counts the log files a run opens (`opens`, `hook_opens`, and `remote_opens` from a `sitecustomize` on the fake remote's `PYTHONPATH`, which also gives it a deterministic `.zst` decoder); `remote_listing` snapshots the fake host to prove it stays unmodified. Progress shows `N changed of M files`; `CCTRACK_TIMING=1` adds a `cache` phase and `; cache: N reused, M read` to each parse phase (and to `hook read` and `remote <host>`, plus `on <host>: encode`, `local: decode`, `local: merge` sub-lines). User-facing docs: README "Parse cache" and the `parse cache` group in `--help`; `tests/test_docs.py` pins both.
5. **Aggregation** (`aggregate`) - Buckets events into daily and monthly summaries with token counts and costs. Reads the energy scale once per call. Pricing runs once per source inside `reconcile_sources` (which overwrites every source's `daily`) and once for the final report; `main` must not add `aggregate` passes whose results reconcile overwrites (sources start with `daily: {}`).
6. **Output** (`print_report`) - Prints current month-to-date summary with projections, daily breakdown, and previous month summaries. Cost is composed **per source** (one source per machine): hook cost where a source has statusline coverage, accuracy-factor-adjusted JSONL cost otherwise, summed per date. The accuracy factor is measured per source over dates strictly after that source's hook install day; when unmeasurable, `DEFAULT_ACCURACY_FACTOR` is **1.0** — the old 1.25 "logs undercount ~20-25%" was entirely rate-card error and inflated unmeasured days 25%.
6a. **Explore** (`print_explore`, `--explore DATE`) - Drills into one day: dollar decomposition by token class, then by model / project / session / machine. Each JSONL event carries its `project` (from `cwd`), `session_id`, `source` (host) and `git_branch` for attribution. Per-session JSONL estimate is shown against the hook's authoritative per-session cost; a >15% day-total divergence is flagged so an inflated estimate (incomplete logs, unknown model) is distinguishable from real spend.
6b. **Detailed reports** (`run_detail_report`, `build_session_rows`, `build_bucket_rows`, `build_coverage`, `build_document`, `write_csv`; flags `--sessions --bucket --coverage --json --csv --since --until --redact --billing-mode`) - Everything UTC; `--since/--until` are a half-open window and are rejected without one of these views. Session key = (agent, host, sandbox, session id, subagent id): Claude sidechain turns (`isSidechain`, `agentId`, else the `agent-<id>.jsonl` filename) are separate rows linked to the parent sessionId; Codex threads use the record's `thread_id` (a fork's replayed records stay with the parent) and get a parent from `session_meta` (`source…parent_thread_id`, `forked_from_id`, or `session_id` ≠ `id`). Parsers fill per-file stats (`new_parse_stats`: lines, unparseable lines, records, timestamp range, compactions keyed by marker so resume replays don't double count) only when asked. Remote streams carry each file's path after the separator. Hook cost is day-granular, so it's attached only for day-aligned windows. Output is ids/paths/counts/money only; `SCHEMA_VERSION` must be bumped on any breaking field change.

7. **Timing** (`timing_enabled`, `_Timing`, `_file_census`, `_note_remote_timing`) - `CCTRACK_TIMING=1` prints `[timing]` lines to **stderr only** when the run ends (also when interrupted): wall time per phase (startup, discovery, claude/codex parse, aggregate, hook read, `remote <host>`, reconcile, report; the `aggregate` phase includes the per-source pricing inside `reconcile_sources`), file/byte census per log kind (done after the clock stops), and for each `--remote` host its own phase breakdown (`_remote_collect(..., timing=True)` adds a `timing` key to the v1 reply; with timing off the program sent to the host is byte-identical). `tests/test_cache_equivalence.py` is the equivalence harness every cache step extends: a fixture corpus plus helpers that run `cctrack` as a subprocess in every mode x variant and compare stdout. `scripts/bench_cache.py` builds a synthetic home and times runs.

Entry point: `cctrack:main` (registered in `pyproject.toml` as a console script).

## Key Design Decisions

- Zero external dependencies - stdlib only (json, argparse, subprocess, etc.)
- Deduplication is global across files, Sandy sandboxes and hosts by API identity, with fullest-snapshot selection. Rsync copies can share request/response ids across hosts. Preserve all copy locations and rebuild per-source totals after dedup. Raw hook histories are also merged before differencing; legacy monthly rollups lack the identities needed to dedup copied summaries reliably.
- Hook data is authoritative for **cost only**; every token count comes from the JSONL logs. Never mix the two in one figure - the hook's token fields are snapshots and would double count against JSONL cache columns.
- Never let one machine's hook coverage suppress another machine's JSONL cost - compose per source.
- Each coding agent is its own source. Codex sources are `exact`: priced straight from their logs, never replaced by the Claude hook and never scaled by the (Claude-derived) accuracy factor. In `--explore`, hook comparisons use only the Claude slice of the JSONL total.
- The parse cache stores only per-file parse results (`{events, stats}`, encoded before any cross-file dedup), never prices, totals or cross-file results. An entry is valid while the file's `(size, mtime_ns)` and the code key (whole-module sha256 + interpreter + text encoding) match, so any cctrack upgrade re-reads everything. stdout must be byte-identical with the cache off, cold, warm or rebuilt; `tests/test_cache_equivalence.py` is where that is proved.
- Costs are API list prices. For subscription users (ChatGPT plans, Claude subscriptions) they're API-equivalent values, not invoices.
- Cumulative counters from the hook are not monotonic and don't start at zero when first observed. `compute_hook_deltas` books only observed upward increments (first observation and post-drop levels are baselines, never counted), so a day's hook cost can never exceed the counter's peak and a session's pre-observation history is never mis-dated onto its first-seen day. Test fixtures must start sessions at ~$0 to mirror real statusline behavior.
- `session-baselines.json` carries each session's rolled-up cumulative across the 90-day retention boundary so straddling sessions aren't re-counted from zero.
- Build system is Hatch (`hatchling`)
- Requires Python 3.10+

## Accounting compatibility

- `tests/test_accounting.py` and `tests/fixtures/ccusage-parity.json` pin synthetic reference cases to ccusage 20.0.34. `scripts/compare_ccusage.py` optionally checks an installed binary in isolated temporary homes; no Node/network requirement for ordinary tests or runtime.
- Provider rules take precedence over matching ccusage. Historical Sonnet 4/4.5 context premiums apply to the whole request, including cache input in the threshold; ccusage's marginal calculation is an intentional documented difference.
- Service tiers come from log metadata, never retrospectively from the user's current config. Explicit model aliases must not absorb arbitrary suffix variants. JSON rate metadata includes service-tier multipliers; session rows include tier counts and copy locations. Redaction must cover all added paths/cwds.
